# Profile setup and operating notes

## Register the profile

1. Publish this repository on GitHub with `profile.py` at its root.
2. In POWDER, choose **Experiments → Create Experiment Profile**, select the
   repository-based mode, and enter this repository's public HTTPS URL.
3. Name the profile **Exploring-the-AI-RAN**, set the project/access policy, and
   save it. Distribute the profile link generated by POWDER.
4. Before class, instantiate the published revision on a fresh d430 and complete
   the [student procedure](../docs/EXPLORING_AI_RAN.md).

After a repository update, push the commit and refresh the POWDER profile to
that revision before instantiating. Rebooting an existing node does not fetch
new GitHub commits.

POWDER places the source at `/local/repository`. The profile automatically runs:

```bash
sudo /bin/bash /local/repository/ai-ran/setup.sh
```

Preparation has no arguments. It installs host packages and pinned Python
dependencies, retrieves pinned OAI/FlexRIC/compiler/SIMDe sources, builds them,
and pulls digest-pinned core images. Allow time for the initial compilation.
Network actors are left stopped so their connection handshakes can be captured.

Setup adds existing regular login accounts under `/users` or `/home` to the
`docker` group and verifies Docker access as each account. This works when
POWDER invokes startup as root. The account list is recorded in the setup
manifest. Reconnect any SSH sessions opened before preparation finished so
commands such as `docker ps` use the new group membership.

## Locations

| Location | Content |
| --- | --- |
| `/opt/oai-anomaly-detection` | This repository, model/data, and configurations |
| `/opt/flexric` | Near-RT RIC, xApp, and decoder build |
| `/opt/openairinterface5g` | gNB and software UE build |
| `/opt/openairinterface5g-telnet` | Pinned telnet-library worktree |
| `/opt/asn1c-src`, `/opt/simde` | Pinned build dependencies |
| `/opt/ai-ran` | Private libraries, Python environment, configuration, and entry points |
| `/var/log/ai-ran` | Preparation, actor, traffic, and command logs |
| `/var/tmp/ai-ran/captures` | Packet captures and decoded messages |
| `/var/tmp/ai-ran/exports` | Exported student evidence bundles |

Preparation progress is recorded in `/var/log/ai-ran/setup.log`. Successful
preparation creates `/opt/ai-ran/READY`; failures are recorded in
`/var/log/ai-ran/setup-failure.txt`. Source pins and package versions are recorded
in `/opt/ai-ran/setup-manifest.json`.

The fixed setup uses GCC12, a pinned historical ASN.1 compiler, explicit
dependency installation, and separate telnet libraries. The included patches
address slice-control concurrency and control-acknowledgment ordering. This core
configuration uses HTTP/1 SBI, explicit NRF addressing, and direct NRF SMF
selection; NSSF is deployed but not used for that selection.

The comparison runner measures receiver goodput, UE2 RTT/loss, and UPF-container
CPU utilization, following the paper's Figure 7 resource metric. Container CPU
uses cgroup counters; host/process CPU and memory are supplementary diagnostics.

The profile installs these comparison tools automatically during startup.

## Operating the lab

Follow the staged commands in the handout. The controller uses two detector
connections and fixed UE-ID assignments, so start UE1 before UE2. After a
release experiment, export the evidence, run `sudo /opt/ai-ran/bin/stop-lab`, and
repeat the startup sequence from `start-core` for another trial.

Use one topology per node: the container names, Compose project, namespaces,
and service ports are fixed. `stop-lab` preserves captures and database volumes.
A capture started with an existing filename overwrites that capture.

The supplied model is used for inference and offline evaluation without
retraining. The lab demonstrates functional control-loop behavior; the handout
explains the custom E42/reporting interfaces and the separate telnet release
path.
